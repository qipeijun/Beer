# 夏日啤酒指南 Apple 式产品页导购版设计稿

## 背景

当前站点已经具备完整的基础导购能力，包括：

- Hero 与品牌说明
- 人群 / 口感 / 产地 / 风格 / 价格带 / 关键词筛选
- 精选卡片列表
- 单品详情弹层
- 选酒提示、价格说明与图片来源信息

但当前体验仍然更像“精装修资料目录页”，主要问题有三点：

1. 第一屏缺少足够明确的高级感，用户进入后能看懂，但不够想继续逛。
2. 上半区的品牌感、下半区的筛选效率和结果呈现之间，缺少一条顺滑的节奏线。
3. 筛选、结果反馈和详情层虽然可用，但还没有形成“产品在帮用户做决策”的感受。

本次改造目标不是把页面做成纯营销落地页，也不是追求重电影感氛围，而是在保留导购效率的前提下，把它升级成更接近 Apple 产品页气质的高端选择工具：克制、干净、强层次、交互轻盈。

## 目标

### 产品目标

1. 将站点从“啤酒资料页”升级为“高端产品页式导购工具”。
2. 保留现有筛选能力，不牺牲用户快速缩小范围的效率。
3. 让首屏、场景入口、筛选控制台、结果卡和详情层使用一套统一的产品语言。
4. 让不懂术语的用户也能从场景入口快速开始，同时让有明确偏好的用户继续高效直筛。

### 体验目标

1. 首屏第一眼更高级，但不依赖厚重暗黑氛围和强戏剧化表达。
2. 页面滚动时从品牌感自然过渡到场景导购，再进入理性筛选，不出现割裂。
3. 筛选区和结果区更像专业产品控制台，而不是大表单加卡片堆叠。
4. 桌面端更有发布页质感，移动端保持紧凑、顺手、好扫读。

### 非目标

1. 不引入 3D、WebGL 或重型滚动编排。
2. 不重写数据模型、筛选逻辑或内容来源。
3. 不新增新的业务筛选维度。
4. 不用屎山式兜底去猜字段、猜映射、猜视觉状态。

## 用户与使用场景

### 核心用户

- 想快速挑到适合夏天饮用啤酒的普通消费者
- 对啤酒有兴趣，但不想先学习复杂术语的用户
- 更看重“今晚喝什么合适”而不是系统研究酒类知识的用户

### 核心场景

1. 用户刚进入页面，希望第一屏就感受到品质感，并愿意继续往下逛。
2. 用户不想先理解术语，而是想从“清爽 / 聚会 / 果香 / IPA 进阶”这样的使用场景切入。
3. 用户已经有偏好，直接使用筛选器快速收窄范围。
4. 用户点开单品后，希望看到更像产品介绍页的整合信息，而不是普通信息弹窗。

## 总体设计方向

采用“发布页骨架 + 导购内核”的路线。

这条路线的关键不是把页面做成纯展示，而是让它在视觉上更像高端产品页，在使用上仍然是高效工具：

- 首屏改成更明亮、更克制的产品发布页气质
- 场景入口收成统一的能力卡，而不是情绪海报
- 筛选区升级为真正的控制台，强调状态反馈与结果摘要
- 结果卡与详情层使用更整洁的产品信息层级

整体参考方向更接近 Apple 官方产品页，而不是酒吧 campaign 或情绪化专题页。视觉关键词是：

- 克制
- 明亮
- 干净
- 高级材质
- 强排版层次
- 轻交互反馈

## 信息架构与页面结构

页面保持五段式结构，但每一段的表达方式调整为更偏产品页：

1. 产品发布页式 Hero
2. 场景能力入口
3. 高级筛选控制台
4. 编辑精选结果区
5. 展开式详情层

原有 `notes` / `about` / `credits` 区块继续保留，但要统一进新的视觉系统，作为下半段补充阅读内容，不再与主导购区抢注意力。

## 详细设计

### 1. 产品发布页式 Hero

#### 结构

- 顶部导航保留，但弱化成更轻的产品页导航
- Hero 主区域保持接近首屏高度
- 由以下内容构成：
  - 简短 eyebrow
  - 强主标题
  - 一句副文案
  - 主 CTA：开始选酒
  - 次 CTA：浏览场景
  - 指标条：总单品数、覆盖国家/地区、核心决策维度

#### 视觉要求

- 从当前偏深色电影感收成“浅暖基底 + 克制高光 + 真实酒图”的方向
- 允许局部玻璃质感，但只作为点缀，不让整个页面毛玻璃泛滥
- 文案区以大留白、短文案、强字号建立高级感，而不是靠大段说明和厚卡片
- Hero 图像优先使用现有真实图片或经过克制裁切的资产，不用抽象大渐变代替主视觉
- 首屏整体观感应更像高端消费电子产品页，而不是酒类品牌宣传片封面

#### 交互要求

- Hero 文案、按钮、指标条在加载时轻微渐入与上移
- CTA 点击仍然滚动到对应区块
- 可以保留极轻微的视差或背景位移，但必须是低风险、低成本、低干扰实现

### 2. 场景能力入口

#### 目标

给不懂术语的用户一个明确入口，但视觉表达更像产品能力切换，而不是内容海报区。

#### 建议场景

- 清爽解暑
- 朋友聚会
- 果香轻松喝
- IPA 进阶

命名可微调，但必须严格映射到现有筛选逻辑，不新增兜底规则。

#### 结构

- 使用统一尺寸的大卡片或等比能力卡
- 每张卡包含：
  - 场景标题
  - 一句短描述
  - 一张代表酒图或风格图

#### 行为

- 点击卡片后，直接写入对应筛选条件，并滚动到结果区
- 当前选中的场景有明确高亮
- 用户后续手动改筛选时，若不再满足该预设，场景高亮取消
- 不强做复杂双向绑定，不引入难以维护的状态补偿逻辑

### 3. 高级筛选控制台

#### 目标

保留现有筛选效率，但把“表单感”降下来，把“决策感”提上来。

#### 结构

- 保留现有筛选维度：
  - 人群
  - 口感
  - 产地
  - 风格
  - 价格带
  - 关键词
- 增加更明确的状态反馈区：
  - 当前条件摘要
  - 当前结果数
  - 一句系统式推荐提示
- 保留清空条件按钮

#### 桌面端布局

- 左侧为筛选控件面板，右侧为摘要和结果反馈
- 控件外层更薄、更轻、更整齐，避免像传统后台表单
- 摘要区要成为视觉焦点之一，让用户一眼知道系统当前在帮他筛什么

#### 移动端布局

- 保留当前可折叠思路，但提升为更像抽屉或展开控制层
- 顶部按钮明确展示当前结果数和激活状态
- 展开后控件布局紧凑但不能拥挤，字段之间要有稳定节奏

#### 行为

- 修改筛选后，结果区使用柔和过渡更新
- 摘要文案实时更新，语言更像判断提示，而不是机械字段拼接
- 清空条件操作要恢复完整默认态，包括摘要、结果数和场景状态

### 4. 编辑精选结果区

#### 目标

把结果区从“信息卡片列表”升级为更像编辑精选墙。

#### 结构

- 顶部保留：
  - eyebrow
  - 标题
  - 简短说明
  - 当前结果数
- 下方继续使用网格列表，但卡片信息层次重新组织

#### 卡片设计原则

- 图片比例更稳定，视觉权重更高
- 文本更少，但层级更明确
- 品牌、酒名、风格、价格带形成稳定主次
- 标签克制显示，只保留最有价值的几项
- “真实图 / 生成图”标识继续保留，但视觉收敛，不抢主体

#### 交互

- hover 使用轻微抬升、亮度变化和阴影变化
- active 卡片状态明确，但不用粗暴厚边框
- 卡片进入视口时可有分批入场动效，但必须轻

#### 空状态

- 保留无结果提示
- 文案语气更自然，例如“放宽一个条件再看看”
- 空状态仍要保留控制感，不能像报错

### 5. 展开式详情层

#### 目标

保留现有详情弹层机制，但体验升级为更像展开的产品页。

#### 结构

继续保留现有信息块：

- 主图与场景补图
- 品牌 / 酒名 / 国家 / 风格
- 推荐理由
- 快速判断
- 怎么喝更对
- 补充信息

#### 视觉要求

- 大图更突出
- 文本分组更清楚
- 信息区块通过留白、节奏和弱边界来区分，而不是堆很多重卡片
- 桌面端更像内容层展开，移动端更像全屏产品详情

#### 动效要求

- 打开时像内容层浮出和展开，而不是原生 dialog 硬弹
- 关闭时平滑回到列表态
- 动效以增强质感为目标，不做夸张特效

## 视觉系统

### 色彩

- 主背景改为浅暖中性色，不再以整页深色夜幕为主
- 主强调色仍围绕金色 / 琥珀色，但只做重点提亮
- 可用少量冷灰蓝做平衡
- 整页需要避免再次滑向“整站棕色”或“重暗黑电影风”

### 材质

- 局部允许玻璃质感、反射、高光和模糊
- 材质要服务信息层次，而不是抢信息
- 玻璃效果只应出现在 Hero、摘要面板、少数重点模块

### 字体与排版

- 继续使用当前无衬线系统
- Hero 标题更短、更大、更像发布页文案
- 各区块正文减量，优先让版式和节奏说话
- 小标题、辅助说明、指标数字之间要形成稳定层级

### 图片策略

- 优先使用现有真实图和已整理过的网页尺寸图片
- Hero 和卡片可做更克制的裁切与版式组合
- 不依赖新增联网素材作为这次改造前提

## 文案语气

页面文案要从“资料解释口吻”调整为“高端导购口吻”，但不是空泛品牌文案。

要求：

- 更短
- 更像判断
- 更少术语说明
- 更强调使用场景

例如：

- “今晚喝什么，先被系统收拢好。”
- “从清爽、聚会到 IPA 进阶，先按你真的会用的路径筛。”
- “系统已经替你把范围缩到更值得先看的几支。”

文案必须基于真实筛选状态与真实内容输出，不制造脱离实际的描述。

## 动效边界

### 应该做

- Hero 渐入
- Section 滚动显现
- 卡片 hover 微动效
- 筛选结果柔和过渡
- 详情层顺滑开合

### 不做

- 重型连续滚动驱动动画
- 夸张 3D 翻转
- 粒子、闪烁、持续高频光效
- 影响阅读和性能的长时间动画

## 数据与逻辑约束

1. 继续沿用现有数据结构与筛选逻辑。
2. 场景入口仅使用现有字段完成映射。
3. 不增加屎山式兜底逻辑，不在字段不确定时自行猜测来源。
4. 保持现有详情内容来源，不额外引入复杂异步行为。
5. 所有状态提示、摘要文案和动效都必须基于真实页面状态。

## 响应式策略

### 桌面端

- 强调发布页气质和留白节奏
- Hero 保持较强视觉冲击力
- 场景卡、筛选控制台和结果区之间要有明显层次
- 详情层保持更完整的展开感

### 平板端

- 保留首屏质感，但适当压缩垂直高度
- 场景卡允许两列或横滑
- 控制台从左右分栏收成上下堆叠

### 移动端

- 首屏文案更短，按钮更紧凑
- 场景卡改为横滑或单列节奏
- 筛选区以折叠 / 抽屉方式承载
- 结果卡单列，保证图片比例和信息层次稳定
- 详情层采用接近全屏的沉浸式阅读

## 验收标准

1. 首屏从“资料目录页”明显升级为“Apple 式高端产品页导购”。
2. 用户可以通过场景入口或筛选器两种方式顺畅进入选酒流程。
3. 筛选区明显更像控制台，当前条件摘要与结果反馈更清楚。
4. 结果卡和详情层视觉层次明显优于当前版本。
5. 页面在桌面和移动端都保持清晰、稳定、不拥挤。
6. 动效轻盈、有质感，不影响性能与阅读。

## 风险与控制

### 风险

1. 过度追求视觉质感，导致筛选效率下降。
2. 过度使用玻璃和高光，导致界面发飘、发花。
3. 首屏过亮或过淡，失去酒类内容该有的质感。
4. 移动端在强化层次后出现信息拥挤。

### 控制方式

1. 始终以“可用导购页”为主线，而不是纯展示页。
2. 把材质集中在少数重点区域，避免全页泛滥。
3. 用真实酒图和稳定排版维持内容质感，而不是靠重特效。
4. 每完成一层视觉升级，都同步检查桌面和移动端的可读性与点击效率。

## 推荐实施方案

采用“方案 C：发布页骨架 + 导购内核”实施：

- 重构 Hero 为产品发布页式首屏
- 将场景入口收为统一能力卡
- 升级筛选区为控制台
- 重组结果卡的视觉层级
- 将详情层升级为展开式产品页体验

该方案最适合当前项目：既能把第一眼气质拉起来，也能把真正高频使用的筛选与结果交互一起做好。
